# Автоматическая регистрация дочерних модулей

`Module.after_init!` автоматически обнаруживает непосредственные поля типа
`Module` после успешного конструктора. Имя поля становится именем в реестре:

```sputnik
class Model < Module:
  def init():
    @features = Sequential([Linear(2, 4), ReLU()])
    @head = Linear(4, 1)
```

`parameters`, `named_buffers`, `state_dict`, `train!`, `eval!` и проверки
stateful forward используют обнаруженное дерево. Hook наследуется независимо
от переопределения `init`. Если конструктор не создавал реестры, hook создаёт
их перед обходом. Явная регистрация во время `init` по-прежнему требует
`_initialize_registry!` до первого обращения к реестрам.

Явно зарегистрированные дочерние объекты пропускаются при автообходе. Это
сохраняет существующие alias (`query` для `@query_projection`, `input` для
`@input_projection`) и ключи checkpoint. Несколько автоматически обнаруженных
полей могут ссылаться на один объект, сохраняя каждый путь в дереве. Повторный
вызов hook не создаёт дубликаты. Обход полей имеет лексикографический порядок;
порядок ранее вручную зарегистрированных элементов сохраняется.

`ModuleList`, `ModuleDict` и `Sequential` регистрируют свои элементы сами.
Обычные Array/Map не обходятся рекурсивно. Поля Tensor автоматически не
классифицируются: `register_parameter!` и `register_buffer!` остаются явными.
После создания изменение состава модели требует API реестров/контейнеров;
присваивание поля само по себе не обновляет регистрацию. Переопределение
`after_init!` в пользовательском классе заменяет стандартное обнаружение.

Проверка: `tools/build tests/auto_registration.s --run-vm`, затем
`tools/build tests/auto_registration.s` и запуск созданного native binary.
